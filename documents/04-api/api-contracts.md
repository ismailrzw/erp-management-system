## Standards

### Response Envelope

Every API response — success or error — uses the same structure:

```json
{
  "success": true,
  "message": "Human-readable description of the result.",
  "data": { ... }
}
```

- `success`: `true` for 2xx responses; `false` for 4xx/5xx responses
- `message`: Always present — display this to the user in toasts
- `data`: Present on success; `null` or absent on errors

### HTTP Status Codes

| Code | When Used |
|------|----------|
| `200` | Successful read or update |
| `201` | Successful create |
| `400` | Bad request — missing or invalid fields |
| `401` | Not authenticated — no token or expired token |
| `403` | Authenticated but wrong role |
| `404` | Requested resource not found |
| `409` | Conflict — duplicate (e.g., student already in a group) |
| `422` | Validation error — field format is wrong |
| `500` | Internal server error — not the client's fault |

### Authentication

All protected endpoints require:
```
Authorization: Bearer <jwt_token>
```

Public endpoints: `POST /api/auth/login` only.

### Pagination

List endpoints that return large collections support pagination via query parameters:
- `?page=1` — page number (1-indexed, default: 1)
- `?limit=20` — items per page (default: 20, max: 100)

Paginated responses include:
```json
{
  "success": true,
  "message": "...",
  "data": {
    "items": [...],
    "total": 150,
    "page": 1,
    "limit": 20,
    "pages": 8
  }
}
```

### Soft Delete Convention

Soft-deleted items are excluded from all list queries unless `?deleted=true` is added (restores/recycle-bin views). Hard-delete routes are explicitly labelled.

## Auth Endpoints

### `POST /api/auth/login`

**Role:** Public (no token required)

**Request Body:**
```json
{
  "email": "manager@bnu.edu.pk",
  "password": "Admin@BNU2026"
}
```

**Success (200):**
```json
{
  "success": true,
  "message": "Login successful.",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "user": {
      "id": "665f2a...",
      "name": "PBL Manager",
      "email": "manager@bnu.edu.pk",
      "role": "pbl_manager",
      "dept": null
    }
  }
}
```

**Errors:** `400` missing fields; `401` invalid credentials

---

### `GET /api/auth/me`

**Role:** Any authenticated user

**Success (200):** Returns current user profile from JWT claims.

---

### `POST /api/auth/change-password`

**Role:** Any authenticated user

**Request Body:**
```json
{
  "currentPassword": "Admin@BNU2026",
  "newPassword": "NewSecure@2026"
}
```

**Success (200):** `{ "message": "Password changed successfully." }`

**Errors:** `400` wrong current password; `400` new password too short

## Manager Endpoints

### Students

---

#### `POST /api/manager/students`
**Role:** `pbl_manager`

**Request Body:**
```json
{
  "name": "Muhammad Ismail Rana",
  "roll": "BCSM-F23-551",
  "dept": "SE",
  "section": "A",
  "session": "Fall 2025",
  "course": "Final Year Project - Fall 2025",
  "teacher": "Dr. Sarah Ahmed",
  "recovery_email": "ismail.rana@gmail.com"
}
```

**Auto-generated by server:**
- `email` = `BCSM-F23-551@bnu.edu.pk` (roll + domain, uppercase)
- `password_hash` = bcrypt hash of initial password (sent to student's recovery_email; mocked in dev)
- `role` = `student`

**Success (201):**
```json
{
  "success": true,
  "message": "Student added successfully. Credentials will be sent to recovery email.",
  "data": {
    "id": "665f2a...",
    "email": "BCSM-F23-551@bnu.edu.pk"
  }
}
```

**Errors:** `409` roll already exists; `422` missing required fields

---

#### `POST /api/manager/students/bulk`
**Role:** `pbl_manager`

**Request:** `multipart/form-data` with `file` field (Excel `.xlsx` or CSV)

**Expected file columns:** `Name, Roll, Department, Section, Session, Course, Teacher, Recovery Email`

**Success (201):**
```json
{
  "success": true,
  "message": "Bulk import complete.",
  "data": {
    "imported": 45,
    "skipped": 2,
    "errors": [
      { "row": 3, "roll": "BCSM-F23-554", "reason": "Roll already exists." }
    ]
  }
}
```

**Errors:** `400` invalid file format; never silent partial success

---

#### `GET /api/manager/students`
**Role:** `pbl_manager`

**Query Params:** `?dept=SE&section=A&search=Ismail&page=1&limit=20&deleted=false`

**Success (200):** Paginated student list

---

#### `GET /api/manager/students/<student_id>`
**Role:** `pbl_manager`

**Success (200):** Single student document

---

#### `PUT /api/manager/students/<student_id>`
**Role:** `pbl_manager`

**Request Body:** Any subset of student fields (name, section, course, teacher, recovery_email)

> [!IMPORTANT]
> `email` and `roll` cannot be changed after creation (they are the student's permanent identity). `dept` changes are allowed but require verifying no active group membership exists.

**Success (200):** Updated student document

---

#### `DELETE /api/manager/students/<student_id>`
**Role:** `pbl_manager`

**Action:** Soft-delete (`deleted: true`). Student is removed from any active groups.

**Success (200):** `{ "message": "Student soft-deleted and removed from groups." }`

---

#### `POST /api/manager/students/<student_id>/restore`
**Role:** `pbl_manager`

**Action:** Sets `deleted: false`.

**Success (200):** `{ "message": "Student restored." }`

---

#### `DELETE /api/manager/students/<student_id>/permanent`
**Role:** `pbl_manager`

**Action:** Hard delete — permanently removes from database. Only allowed if student is already soft-deleted.

**Errors:** `400` if student is not already soft-deleted

## Student Endpoints

### Groups

#### `POST /api/student/groups`
**Role:** `student`

**Body:** `{ "name": "AI Chatbot Team" }`

**Server enforces:**
- Student's course and section are read from JWT claims
- Student must not already be in a group in this course (checked against `groups.member_ids`)

**Success (201):** New group document with `status: "pending"`, `leader_id` = current user

**Errors:** `409` student already in a group

---

#### `GET /api/student/groups`
**Role:** `student`

**Action:** Browse all groups in the same course and section as the current student.

**Query:** `?search=...&status=approved`

**Success (200):** List of groups with member count and pending request status for current student

---

#### `GET /api/student/groups/my`
**Role:** `student`

**Success (200):** The student's current group with full member details, or `null` if not in a group

---

#### `POST /api/student/groups/<id>/join-request`
**Role:** `student`

**Body:** `{ "message": "I am interested in joining." }` (optional)

**Validation:**
- Student must not already be in a group in this course
- Student must not already have a pending request for this group
- Group must be `approved` and not full

**Success (201):** `{ "message": "Join request sent." }`

**Errors:** `409` already requested or already in a group; `400` group is full

---

#### `DELETE /api/student/groups/<id>/join-request`
**Role:** `student`

**Action:** Cancel own pending join request

---

#### `GET /api/student/groups/my/join-requests`
**Role:** `student` (must be group leader)

**Success (200):** List of pending join requests for the student's group

---

#### `PATCH /api/student/groups/my/join-requests/<request_id>/accept`
**Role:** `student` (must be group leader)

**Validation:**
- Group must not be full after adding this student
- Uses optimistic locking (`version` field) to prevent race conditions

**Server action:**
1. Increment `groups.version`
2. Add student to `groups.member_ids`
3. Set this request to `accepted`
4. Cancel all other pending requests from this student across all groups in this course

**Success (200):** `{ "message": "Join request accepted. Student added to group." }`

**Errors:** `409` group is full; `404` request not found; `403` not the leader

---

#### `PATCH /api/student/groups/my/join-requests/<request_id>/reject`
**Role:** `student` (must be group leader)

---

#### `DELETE /api/student/groups/my/leave`
**Role:** `student`

**Validation:**
- If student is the leader and there are other members, leadership is transferred to the next member
- If student is the only member, the group is deleted

**Success (200):** `{ "message": "You have left the group." }`

---

### Evaluations

#### `POST /api/evaluator/evaluations`
**Role:** `evaluator`

**Body:**
```json
{
  "group_id": "665f2a...",
  "iteration_id": "665f2b...",
  "scores": { "1": 4, "2": 3, "3": 5, "4": 4 },
  "comment": "Good proposal. Methodology needs detail."
}
```

**Validation:**
- Evaluator must be assigned to this group
- Score keys must match rubric question IDs for this iteration
- Score values must be 0–5 integers
- Cannot submit twice for same (group, iteration, evaluator) — unique constraint

**Server computes:** `total_weighted_score`; sets `locked: true`

**Success (201):** `{ "message": "Evaluation submitted and locked." }`

**Errors:** `409` already evaluated; `403` not assigned; `400` invalid scores

---
